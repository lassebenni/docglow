# Evaluate PR — docglow

**Extends the global `/evaluate-pr`. Does not replace it.**

> **First action: read `~/.claude/commands/evaluate-pr.md` (or the Cursor
> `/evaluate-pr` command if that is what this session loaded) and follow it end
> to end.**
> That file owns the pipeline — base sync, diff fetch, the sub-agent critique
> criteria (including *correctness by execution* and *comment quality*), the
> `advisor()` second opinion, the report skeleton, and the read-only /
> never-merge rules. Nothing there is restated here; if the two ever disagree,
> the global file wins.

## Two layers, one report

`/evaluate-pr-docglow` = global critique + docglow overlay. See `evaluate-pr.md`
§ Superset commands for the merge rule (both mandatory, one combined report —
not restated here). Overlay letters map to domains as follows:

| Layer | Source | What it covers |
|---|---|---|
| **Global** | `~/.claude/commands/evaluate-pr.md` steps 1–5 | Necessity, DRY, SRP, placement, cross-PR scope, extendability, correctness-by-execution, comment quality |
| **Overlay** | This file (A, A2, B, B2, D) | Path routes, static-bundle / shared-types traps, fork vs upstream, vt-dbt consumer blast radius |

This file adds only what is specific to **`lassebenni/docglow`** (the
VanTilburg / vt-dbt fork of `docglow/docglow`).

`.github/copilot-instructions.md`, `CLAUDE.md`, and `PORTING_TODO.md` are the
canonical fork review context — **do not restate them here**. Cite them; a
second copy drifts and produces false findings. Prefer fewer, higher-signal
comments over style nits those docs already mark out-of-scope.

## Input

A GitHub PR number or URL: $ARGUMENTS. Defaults to `lassebenni/docglow`.

## Overlay A — route by changed path

Run **after the diff and file list are fetched, before the critique sub-agent is
spawned**. Run every row that matches, and feed what you find into the sub-agent
prompt so domain and structural findings get reconciled rather than arriving as
two lists.

| Changed paths / signals | Route to | Looking for |
|---|---|---|
| `frontend/src/**`, `frontend/src/__tests__/**` | Overlay B (frontend) + correctness-by-execution | Source of truth is TSX/TS under `frontend/src/`. Run `cd frontend && npx tsc --noEmit` and/or `npm run test` for behaviour the PR adds — not a full suite unless cheap. |
| `packages/shared-types/**` | Overlay B (shared-types) | Package rebuild; frontend `types/index.ts` augmentations stay in sync; `file:../packages/shared-types` consumers must still typecheck. |
| `src/docglow/static/**`, especially `static/assets/index-*.{js,css}` | Overlay B (static bundle) | Generated by `npm run build:sync`. Do **not** review hashed JS/CSS as source. Flag orphaned old hashes left beside new ones, or frontend changes without a matching sync. |
| `src/docglow/lineage/**`, `tests/lineage/**` | Overlay B (lineage) | `_CACHE_FORMAT_VERSION` bump when result shape changes; sqlglot edge cases; ProcessPoolExecutor pickling. Prefer `pytest tests/lineage/…` over full suite. |
| `src/docglow/generator/**`, `src/docglow/artifacts/**` | Overlay B (fail-soft / artifacts) | Fail-soft `logger.warning` + continue is intentional. Null-tolerant Pydantic on artifact fields — do not demand hard raises. |
| `src/docglow/profiler/**`, sample-data / Data-tab paths | Overlay A2 + B (PII) | Producer withholds PII; fork renders placeholders. Don't request re-scanning values in the docs site. |
| `assets/verify-*.png`, `INVESTIGATION.md`, one-off `scripts/screenshot_*.mjs` | Necessity | Local verify artifacts / investigation scratch — must not ship in the PR (screenshots are gitignored; notes/scripts belong deleted or out of the PR). |
| `demo-site*/**`, `examples/**/target/**` | Necessity | Generated demo output / dbt target junk — usually dead weight unless the PR is explicitly about fixtures. |
| `.github/workflows/**`, CI config | Placement + correctness | Match sibling workflows; don't break `ruff` / `mypy` / `pytest` / frontend jobs. |
| Cherry-pick / "upstream #N" in title/body | Overlay B (fork vs upstream) | Divergence is allowed; check shared-file regressions (ModelPage, LineageFlow, Header, types) against fork features in `PORTING_TODO.md`. |
| `PORTING_TODO.md` claims a feature is missing | — | Deferred entries are intentional — not a finding unless the PR *claims* to ship them and doesn't. |

Skip what doesn't match. Report which routes ran — a reviewer needs to know
whether a route was actually applied or merely available.

## Overlay A2 — vt-dbt consumer blast radius

The only production consumer today is **`vantilburg/vt-dbt`**, which installs this
fork via `pip install -e <path-to-fork>`. Cross-repo references (e.g. vt-dbt's
`scripts/docglow_data/dump_sample.py`) are real.

Run this when the PR touches payloads, CLI flags, or UI that vt-dbt feeds or
relies on:

1. **Sample Data / PII contract** — producer ships `excluded_columns` (+ optional
   `all_columns`); fork merges withheld columns as `••••` placeholders. Breaking
   that shape without a coordinated vt-dbt change is a **must-fix**.
2. **Manifest / DocglowData fields** — new required fields, renamed keys, or
   dropped optional fields in the generated JSON can break an existing
   `docglow generate` against vt-dbt artifacts. Prefer additive, optional fields.
3. **Editable-install assumption** — this is not a published PyPI library for
   VanTilburg; backwards-compat shims for *internal* fork churn are out of
   scope (see copilot-instructions). Still flag **silent** contract breaks
   against the consumer's dump scripts / `docglow.yml`.
4. For deep "what breaks in vt-dbt docs publish?" evidence, note the sibling
   repo path — do not invent endpoints. This overlay's job is the merge/no-merge
   finding.

If nothing consumer-facing changed, report `consumer blast radius: none`.

## Overlay B — docglow / fork traps

- **Fork, not upstream PR.** Do not block on "could be upstreamed" or "changes
  the upstream contract". Divergence is allowed. Do flag *local* bugs and
  contract drift inside the fork.
- **Static bundle pairing.** Frontend source edits that affect the shipped SPA
  should land with a regenerated `src/docglow/static/` from `npm run build:sync`,
  including **deletion** of stale content-hashed assets. Reviewing only the
  minified bundle (or leaving both old and new hashes) is a finding.
- **shared-types drift.** Changing `packages/shared-types` without rebuilding /
  without updating `frontend/src/types/index.ts` augmentations (the fork still
  carries temporary interface merges until republish) causes `tsc` failures that
  look unrelated — check both sides.
- **Shared-file regressions.** `ModelPage.tsx`, `LineageFlow.tsx`, `Header.tsx`,
  lineage toolbar/`graph.ts` patches, Questions/Data tabs: when merging or
  cherry-picking upstream, confirm fork-only behaviour from `PORTING_TODO.md`
  still works. A lost Parents/Children depth slider or Documentation tab is a
  **must-fix**, not a nit.
- **Fail-soft is intentional** in generator/profiler paths — don't request
  "raise instead of warn" for malformed optional inputs.
- **PII:** don't ask the fork to re-detect PII; trust producer metadata.
- **Lineage cache format.** Shape changes to cached lineage results require
  `_CACHE_FORMAT_VERSION` (or equivalent) bumps — otherwise stale caches lie.
- **Performance findings** only on hot paths called out in
  copilot-instructions (per-model pipeline stages, BFS in `graph.ts`).
  Constant-time / once-per-site work is not interesting.
- **Out-of-scope nits** (do not raise): ruff/eslint style, DRY for <3 sites /
  <10 lines, comment density, rename-for-clarity, type-alias extraction,
  parallelize-the-build suggestions. See copilot-instructions § out-of-scope.

## Overlay B2 — read every changed path, and verify what it asserts

Same two failures Overlay B2 exists to stop in vt-dbt — they apply here too:

**Reviewing a subset.** Enumerate the PR's file list and account for every path
(finding or "read, nothing to report"). Never narrow to `frontend/` or
`src/docglow/` and silently skip `.claude/`, scripts, docs, or static orphans.

**Trusting a file the PR is editing.** Do not hand
`.github/copilot-instructions.md`, `PORTING_TODO.md`, `CLAUDE.md`, or a
skill/command under review to a sub-agent as ground truth when they appear in
the diff. A file under review is evidence to be checked, not a reference to
cite.

**Claims verification for this repo:**

- "build:sync produces X" / "tests pass" → run the cheapest confirming command
  (`pytest` scoped, `tsc --noEmit`, or a single vitest file).
- "upstream #N behaviour" → check the upstream commit/PR, not the author's
  paraphrase.
- Version / cache-format / weight numbers in comments → match the code.

## Overlay C — report additions

Use the **global** report skeleton from `evaluate-pr.md` (severity summary →
numbered findings → TL;DR), with these additions.

**Immediately after the `## PR #<n> — <title>` heading**, before
`**Severity summary:**`, add:

```
**Problem:** <2–4 sentences — what is broken, missing, or risky today; plain English>
**Goal:** <1–3 sentences — what this PR aims to leave true after merge; outcome, not file list>
```

Derive Problem/Goal from the PR body **and** the diff. If the body is empty or
wrong, say so in Goal (“author claims X; diff actually does Y”).

Then insert these lines immediately after `**Severity summary:**`:

```
**Global critique:** ran evaluate-pr steps 1–5 (sub-agent + advisor) — yes / skipped (why)
**Routes run:** <route>, … or "none — no matching paths"
**Consumer blast radius:** vt-dbt sample-data / generate contract touched — yes (detail) / none
**Static bundle:** source-only / source+sync paired / orphaned hashes / n/a
**Paths reviewed:** <n>/<total> changed paths read
**Checks run:** <pytest/tsc/vitest commands actually executed>, or "none — N claimed"
```

Numbered findings below must include **both** global and overlay issues in a
single priority-ordered list (must-fix first). Tag overlay-only traps inline
when helpful, e.g. `[overlay: static bundle]` or `[overlay: fork regression]`.

## Overlay D — extra rules

In addition to the global rules (read-only, never merge, verify placement against
a real sibling, never trust a comment's claim):

- **Distinguish pre-existing from introduced.** Run
  `git show origin/<base>:<file>` before calling anything a regression. A latent
  bug the PR merely moved is a follow-up note, not a blocker.
- **Do not merge** from this command. Do not post PR comments unless the user
  separately asks — draft only.
- **Never push / never commit** as part of evaluate.
- A red CI job is not automatically this PR's fault — compare against recent
  runs on other branches before attributing.
